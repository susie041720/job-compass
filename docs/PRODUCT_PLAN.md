# 产品与开发规划

## 用户与目标

主要用户是希望系统管理个人求职信息、但不熟悉编程的学生或求职者。核心任务是快速记录岗位、知道下一步要做什么，并在面试前找回完整资料。

## 页面结构

| 页面 | 首要任务 | MVP 内容 |
| --- | --- | --- |
| 数据概览 | 快速判断求职进展 | 核心指标、最近更新、阶段分布、下一步建议 |
| 投递记录 | 管理和查找申请 | 搜索、筛选、排序、增删改、进度快速更新、CSV |
| 岗位资料库 | 面试前集中复习 | 公司介绍、JD、要求、面试/笔试资料、问题和笔记 |
| 推荐岗位（二期） | 发现匹配机会 | 合规采集、去重、匹配度、来源和更新时间 |
| AI 分析（二期） | 提高申请质量 | 原文与 AI 内容分区、差距、优先级、简历和面试建议 |

## 数据结构

applications 包含标识与时间、公司与岗位、原始 JD、投递信息以及岗位资料。常用筛选围绕 status、category、location、applied_date、updated_at 建立索引。todos 表已预留，供下一小版本接入首页待办。

第二阶段建议新增 job_sources、job_recommendations 和 ai_analyses。AI 内容单独存表，并在界面中使用“AI 分析”标签，绝不覆盖原始 JD。

## 开发步骤

1. 项目结构、数据库、响应式工作台
2. 增删改查、状态、搜索筛选排序
3. 岗位资料库、CSV 导入导出、统计
4. 示例数据、错误提示、测试、README、环境变量模板
5. 链接/JD 识别、AI 分析、合规岗位推荐
6. 身份验证、数据隔离、隐私检查、公开部署

## 二期匹配分建议

总分 100：岗位方向 35、技能关键词 30、专业背景 20、地点偏好 10、发布时间 5。每一项显示具体依据，用户可以调整权重。

## 风险与边界

- 不抓取要求登录、验证码或明确禁止自动访问的网站。
- 不把 API Key、简历正文和个人联系方式提交到公开仓库。
- 当前 MVP 是个人使用模式；公开部署并存放真实数据前必须添加身份验证。
- 自动识别和 AI 结果需要人工确认后才能写入核心字段。
